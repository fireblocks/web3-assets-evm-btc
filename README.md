# @fireblocks-recovery/assets-evm-btc

**EVM + Bitcoin-only subset** of
[`@fireblocks-recovery/assets`](https://github.com/fireblocks/web3-assets). Pure asset/chain
metadata for Fireblocks tooling - zero runtime dependencies. Defines `NativeAssetConfig` for
every EVM chain (mainnet and testnet, 221 at last generation, including legacy non-standard-coinType
chains like SGB/ETC/FLR) plus BTC and BTC_TEST, auto-generated from `src/blockchains/<chain>/`.
Also exports icon SVGs (`./icons/*`, filtered to the chains in this subset) and the
Fireblocks-supported-assets data file (`./data/tokens.json`, filtered to ERC20 tokens on the
included EVM chains).

This is a **one-time filtered copy**, not a build variant - it was created by deleting all
non-EVM/non-BTC chain directories from `@fireblocks-recovery/assets` and regenerating the
registry. It does not automatically pick up new chains added upstream; re-derive it from the
full package if you need to refresh the subset.

Part of a small family of standalone packages extracted from the `recovery-revamp`
monorepo: [`@fireblocks-recovery/crypto`](https://github.com/fireblocks/web3-crypto) and
[`@fireblocks-recovery/blockchain-evm-btc`](https://github.com/fireblocks/web3-blockchain) (which
depends on this package).

```ts
import { getAssetConfig, SUPPORTED_ASSETS } from '@fireblocks-recovery/assets-evm-btc';

const eth = getAssetConfig('ETH');
```

## Installation

This package has no registry entry - install directly from GitHub (once pushed) or reference it
as a local `file:` dependency:

```bash
pnpm add github:fireblocks/web3-assets-evm-btc
# or: npm install github:fireblocks/web3-assets-evm-btc
# or: yarn add github:fireblocks/web3-assets-evm-btc
```

The compiled `dist/` output is committed to this repo, so there's no build step on install -
works identically with npm, yarn, and pnpm. Pin to a specific commit (`#<sha>`) instead of
`main` if you want a stable, reproducible install for a real application.

## Local development

```bash
pnpm install
pnpm run build
pnpm run type-check
```

## Contributing

**Whenever you change `src/`, rebuild and commit the updated `dist/` output** (`pnpm run
build`) as part of the same change - `dist/` is committed and is what consumers actually
install, so a PR that only changes `src/` won't take effect for anyone installing via git.
There's no CI pipeline wired up yet, so running `build`/`type-check` locally before opening a
PR is currently the only verification gate.

- **New chain**: create `src/blockchains/<chain>/index.ts` exporting a `NativeAssetConfig`.
- **New token**: `src/blockchains/<chain>/tokens/<standard>/<token>.ts` (e.g.
  `blockchains/evm/ethereum/tokens/erc20/usdt.ts`).
- **Icon**: add an SVG to `icons/`, named after the lowercase asset ID (e.g. `icons/eth.svg`).
- Don't hand-edit `src/registry/*.generated.ts` - it's regenerated by `pnpm run
  generate:registry` (runs automatically via the `prebuild` hook).
